# Audit — 2026-11-09

Every module read; findings verified in the code or by running it, in
the order they were fixed in v0.2.0.

## Defects (fixed)

1. **`fetch` URL parsing returned the wrong ID.** Splitting a watch URL
   on `=` returns the last query value: `?v=sVTAtgzPGhA&t=42s` parsed
   as ID `42s` (reproduced). Fixed with real URL parsing (`drawyt/ids.py`).
2. **`download --cc-only` could not be disabled.** `store_true` with
   `default=True`: the flag existed but did nothing. Fixed with
   `BooleanOptionalAction`.
3. **The level-1 judge was dead code.** `BrightRegionJudge` was defined
   and documented in the README's status list as pending wiring, but no
   code path called it. Now wired into `prune`/`fetch` behind `--judge`,
   scores written to the manifest.

## Design gaps (fixed)

4. **Coreset ignored pruning.** It re-read the raw frames folder, so
   frames that level 0 had dropped could be selected. `--from-manifest`
   now restricts selection to kept frames; `fetch --budget` chains the
   stages properly.
5. **No CI, no `python -m drawyt`, no changelog.** All three added; the
   workflow ships as `docs/ci-workflow.yml` because the GitHub App
   integration has no `workflows` permission (its push was rejected
   with 403 on `.github/workflows/`) — one manual copy activates it.

## Known limits (not fixed — recorded, with reasons)

- **Android-route quality cap:** in the measured session the working
  route delivers 360p (SABR experiment). A route-quality problem, not a
  code problem; the default route is tried first wherever it works.
- **Level-0 near-duplicate check is O(kept²)** in hash comparisons.
  Fine at the pilot scale (thousands of frames); bucketed hashing is
  the known fix when a single video's kept set grows past ~50k.
- **Embeddings are histogram-based**, not learned. Deliberate for v0.x
  (zero heavy deps); the `frame_embedding` shape contract is where a
  learned extractor plugs in.
- **Level 3 (disagreement/uncertainty) still open** — it needs the real
  Draw judges (sheet ONNX, ink ONNX, hand landmarker) behind the
  `Judge` interface, which is Draw-side work, tracked in the spec.
